# PostgreSQL data model

## Scope

The Sprint 2 persistence foundation contains four MVP entities: users, jobs,
candidates, and applications. PostgreSQL is the only database. The initial
schema is in `database/init.sql` and is loaded automatically when Compose first
initializes an empty database volume.

All tables use UUID primary keys generated by PostgreSQL with
`gen_random_uuid()`. `created_at` and `updated_at` are `timestamptz` values that
default to the current time; a shared trigger updates `updated_at` when a row
changes.

## Entities

### users

| Field | Type | Rules |
| --- | --- | --- |
| id | uuid | Primary key, generated by default |
| email | text | Required, unique, non-empty |
| full_name | text | Required, non-empty |
| role | text | Required, non-empty |
| created_at | timestamptz | Required, defaults to current time |
| updated_at | timestamptz | Required, defaults to current time, maintained on update |

### jobs

| Field | Type | Rules |
| --- | --- | --- |
| id | uuid | Primary key, generated by default |
| title | text | Required, non-empty |
| description | text | Required, non-empty |
| location | text | Optional |
| status | text | Required, defaults to `open` |
| created_by | uuid | Required foreign key to `users.id` |
| created_at | timestamptz | Required, defaults to current time |
| updated_at | timestamptz | Required, defaults to current time, maintained on update |

### candidates

| Field | Type | Rules |
| --- | --- | --- |
| id | uuid | Primary key, generated by default |
| full_name | text | Required, non-empty |
| email | text | Required, unique, non-empty |
| location | text | Optional |
| years_experience | numeric(5,2) | Optional, cannot be negative |
| skills | jsonb | Required array, defaults to an empty array |
| created_at | timestamptz | Required, defaults to current time |
| updated_at | timestamptz | Required, defaults to current time, maintained on update |

Skills use JSONB with an array shape, for example the stored value is simply
`["Python", "SQL"]`. JSONB is chosen over a PostgreSQL array to keep the skills
field extensible while retaining native JSON querying and validation.

### applications

| Field | Type | Rules |
| --- | --- | --- |
| id | uuid | Primary key, generated by default |
| job_id | uuid | Required foreign key to `jobs.id` |
| candidate_id | uuid | Required foreign key to `candidates.id` |
| status | text | Required, defaults to `applied` |
| matching_score | numeric | Optional |
| created_at | timestamptz | Required, defaults to current time |
| updated_at | timestamptz | Required, defaults to current time, maintained on update |

## Relationships and constraints

- One user can create many jobs; each job has one required creator.
- A job can have many applications; each application belongs to one job.
- A candidate can have many applications; each application belongs to one candidate.
- `applications` has a unique constraint on `(job_id, candidate_id)`, preventing duplicate applications to the same job.
- User and candidate emails are unique. Required text fields reject empty or whitespace-only values.
- Foreign keys use PostgreSQL's default `NO ACTION` behavior; deletions are not cascaded.
- Indexes cover job creator, job status, and both application foreign keys. Unique email and application constraints also provide their corresponding indexes.

## Local verification

Copy `.env.example` to `.env` if you do not already have a local `.env`, then
run `docker compose up -d postgres`. Check readiness with `docker compose ps`
and run the rollback-only SQL smoke test with:

```powershell
Get-Content -Raw .\database\verify.sql | docker compose exec -T postgres psql -U talentpilot -d talentpilot -v ON_ERROR_STOP=1 -f -
```

The SQL smoke test checks connectivity, table presence, insert/select behavior,
and both foreign-key relationships. Its test rows are rolled back.
